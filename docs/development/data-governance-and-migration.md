# 数据治理、迁移与发布方案

## 1. 数据治理原则

1. 主数据统一来源，禁止多模块重复维护。
2. 敏感数据分级授权，默认脱敏展示。
3. 涉密数据按密级、知悉范围和审计规则管理。
4. 业务数据默认软删除。
5. 审批完成、财务、合同、涉密审计数据原则上不可物理删除。
6. 所有导入、导出、迁移均记录日志。

## 2. 主数据归属

| 主数据 | 归属模块 | 被引用模块 |
| --- | --- | --- |
| 用户 | 系统管理 | 全系统 |
| 员工 | 人事管理 | 用户、审批、项目、党建、培训、协作团队 |
| 部门 | 系统管理/人事管理 | 权限、审批、报表 |
| 客户 | 客户管理 | 项目、合同、财务、运维 |
| 联系人 | 客户管理 | 商机、拜访、客户交接 |
| 项目 | 项目管理 | 工程、财务、库存、合同、协作团队 |
| 工程 | 工程管理 | 库存、协作团队、培训、涉密 |
| 合同 | 合同管理 | 财务、客户、项目、供应链 |
| 供应商 | 供应链采购管理 | 合同、库存、财务 |
| 物料 | 库存管理 | 供应链、工程、运维 |
| 党组织 | 党建管理 | 党员、会议、党费、公告 |
| 密级规则 | 涉密管理 | 附件、项目、合同、党建台账 |

## 3. 数据质量规则

| 数据 | 校验规则 |
| --- | --- |
| 用户账号 | 唯一，不允许空格和中文特殊符号 |
| 手机号 | 格式校验，可加密存储 |
| 员工工号 | 唯一 |
| 客户名称 | 同区域同名称需提示重复 |
| 统一社会信用代码 | 18 位格式校验 |
| 合同编号 | 服务端自动生成，唯一 |
| 项目编号 | 服务端自动生成，唯一 |
| 金额 | 非负，保留两位小数 |
| 日期范围 | 开始日期不得晚于结束日期 |
| 附件 | 类型、大小、MIME 必须校验 |
| 涉密对象 | 必须有密级、责任人、保密期限或解密规则 |

## 4. 数据导入策略

### 4.1 导入流程

1. 下载导入模板。
2. 用户填写 Excel/CSV。
3. 上传到导入接口。
4. 服务端预校验。
5. 返回错误明细。
6. 用户修正后再次上传。
7. 校验通过后写入临时表。
8. 用户确认导入。
9. 后台事务写入正式表。
10. 记录导入日志。

### 4.2 导入日志表 `import_logs`

```sql
CREATE TABLE import_logs (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  module        VARCHAR(64) NOT NULL,
  file_name     VARCHAR(255) NOT NULL,
  total_rows    INT NOT NULL DEFAULT 0,
  success_rows  INT NOT NULL DEFAULT 0,
  failed_rows   INT NOT NULL DEFAULT 0,
  error_file    VARCHAR(500),
  status        VARCHAR(16) NOT NULL DEFAULT 'pending',
  created_by    BIGINT UNSIGNED NOT NULL,
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  finished_at   DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5. 历史数据迁移

### 5.1 迁移对象

1. 员工档案。
2. 客户档案和联系人。
3. 项目和工程历史数据。
4. 合同和附件。
5. 库存物料。
6. 供应商和商品。
7. 党员和党组织资料。

### 5.2 迁移步骤

1. 数据盘点：确认来源系统、文件、字段。
2. 字段映射：建立来源字段到目标字段映射。
3. 数据清洗：去重、补齐必填、格式转换。
4. 试迁移：迁移到测试库。
5. 业务核对：各模块负责人抽样核对。
6. 正式迁移：停写窗口内执行。
7. 迁移后校验：记录数、金额、附件数量核对。
8. 归档：保存迁移脚本、日志和核对报告。

## 6. 发布策略

### 6.1 环境划分

| 环境 | 用途 |
| --- | --- |
| dev | 开发自测 |
| test | 测试人员验证 |
| staging | 预生产，接近生产数据结构 |
| prod | 正式环境 |

### 6.2 发布流程

1. 合并代码到发布分支。
2. 执行数据库迁移脚本。
3. 部署 PHP/API 代码。
4. 部署页面和静态文件。
5. 清理缓存。
6. 执行健康检查。
7. 执行冒烟测试。
8. 记录发布日志。

### 6.3 回滚策略

必须准备：

1. 上一版本代码包。
2. 数据库结构回滚脚本。
3. 数据库备份。
4. 文件附件备份。
5. 发布日志和变更清单。

回滚触发条件：

1. 登录不可用。
2. 核心审批不可用。
3. 数据库迁移失败。
4. 严重权限越权。
5. 涉密数据暴露风险。

## 7. 备份和归档

| 数据 | 备份频率 | 保存周期 |
| --- | --- | --- |
| 数据库 | 每日全量 | 不少于 30 天 |
| 附件 | 每日增量 | 不少于 90 天 |
| 涉密审计日志 | 每日增量 | 按制度，建议 3-5 年 |
| 发布包 | 每次发布 | 至少保留最近 10 个版本 |
| SQL 迁移脚本 | 每次变更 | 永久保留 |

## 8. 数据脱敏规则

| 字段 | 展示规则 |
| --- | --- |
| 手机号 | 138****0000 |
| 身份证 | 110101********1234 |
| 银行卡 | **** **** **** 1234 |
| 家庭地址 | 默认隐藏，授权查看 |
| 客户联系人家庭情况 | 默认隐藏，授权查看 |
| 涉密文件名 | 无知悉权限时只显示“涉密资料” |

## 9. 数据保留规则

| 数据 | 保留策略 |
| --- | --- |
| 登录日志 | 至少 1 年 |
| 操作日志 | 至少 3 年 |
| 审批记录 | 随业务单据长期保留 |
| 财务数据 | 按财务制度长期保留 |
| 合同数据 | 合同终止后继续保留 |
| 涉密审计 | 不允许普通删除，长期归档 |
| 临时验证码 | 过期后可定期清理 |

