# 模块契约与数据流边界设计

## 1. 设计目标

现有文档已经定义了模块、数据库、API、事件和页面映射。本文件进一步明确模块之间的“契约”：

1. 哪个模块是某类数据的唯一写入方。
2. 哪些模块只能读取或引用。
3. 哪些动作必须通过同步 API 调用。
4. 哪些动作必须通过异步事件联动。
5. 哪些跨模块修改是禁止的。
6. 发生异常时谁负责补偿。

核心原则：

```text
主数据归属唯一
业务状态由归属模块维护
跨模块只通过 API 或事件联动
禁止直接写其他模块主表
```

## 2. 读写归属总表

| 数据对象 | 唯一写入模块 | 允许读取模块 | 禁止行为 |
| --- | --- | --- | --- |
| 用户、角色、菜单、权限 | 系统管理 | 全系统 | 业务模块直接改权限 |
| 员工档案 | 人事管理 | 项目、审批、党建、培训、协作团队 | 党建或协作团队复制员工主档案 |
| 客户档案 | 客户管理 | 项目、合同、财务、运维、报表 | 合同或项目直接改客户基础信息 |
| 联系人画像 | 客户管理 | 项目、商机、客户交接 | 非客户模块写敏感画像 |
| 商机 | 客户管理 | 项目、合同、报表 | 项目模块直接改商机阶段 |
| 项目 | 项目管理 | 工程、合同、财务、库存、协作团队 | 工程模块直接改项目预算 |
| 项目成本 | 项目管理 | 财务、库存、工程、报表 | 财务直接改项目成本汇总 |
| 工程 | 工程管理 | 项目、协作团队、库存、财务、涉密 | 协作团队直接改工程状态 |
| 施工日志 | 工程管理 | 项目、客户分享、报表 | 第三方直接写日志 |
| 协作团队档案 | 协作团队管理 | 工程、运维、项目 | 工程模块维护外部人员档案 |
| 团队派工 | 协作团队管理 | 工程、运维、客户商机 | 来源模块绕过派工记录 |
| 供应商 | 供应链采购管理 | 合同、库存、财务 | 库存模块改供应商评级 |
| 供应商报价 | 供应链采购管理 | 平台采购授权角色 | 供应商查看其他供应商报价 |
| 物料 | 库存管理 | 供应链、工程、运维 | 供应链采购创建平台物料不审核 |
| 库存流水 | 库存管理 | 工程、运维、财务、报表 | 工程直接改库存数量 |
| 合同 | 合同管理 | 客户、项目、财务、供应链 | 客户模块保存合同正文 |
| 报销、付款、应收 | 财务管理 | 项目、合同、供应链、报表 | 项目模块直接改付款状态 |
| 培训课程 | 培训管理 | 党建、涉密、人事 | 党建模块复制课程资源 |
| 党组织、党员 | 党建管理 | 人事、培训、通知 | 人事模块维护党组织结构 |
| 涉密对象 | 涉密管理 | 被授权业务模块 | 业务模块绕过密级授权 |

## 3. 同步 API 调用契约

同步 API 适合用户操作时需要立即返回结果的场景。

| 调用方 | 被调用方 | API | 场景 |
| --- | --- | --- | --- |
| 页面布局 | 系统管理 | `/api/menus/tree.php` | 获取动态菜单 |
| 项目管理 | 客户管理 | `/api/ref/customers.php` | 选择客户 |
| 项目管理 | 协作团队管理 | `/api/ref/collaboration-teams.php` | 选择团队 |
| 工程管理 | 库存管理 | `/api/ref/materials.php` | 选择材料 |
| 工程管理 | 供应链采购 | `/api/suppliers/inquiries/create.php` | 库存不足触发询价 |
| 财务管理 | 合同管理 | `/api/ref/contracts.php` | 选择付款合同 |
| 党建管理 | 人事管理 | `/api/ref/employees.php` | 选择党员员工 |
| 涉密管理 | 任意业务模块 | `/api/business/relations.php` | 查询业务对象摘要 |

同步调用要求：

1. 调用失败必须返回明确错误。
2. 不允许同步 API 跨模块直接写多张主表，复杂联动改用事件。
3. 同步 API 的事务边界仅限本模块。

## 4. 异步事件契约

异步事件适合跨模块回写、待办、消息、报表、成本归集等场景。

| 事件 | 触发方 | 订阅方 | 原因 |
| --- | --- | --- | --- |
| `project.approved` | 项目管理 | 合同、工程、工作台 | 立项通过后允许后续业务 |
| `engineering.material.requested` | 工程管理 | 库存、供应链采购 | 物料申请和库存不足处理 |
| `inventory.outbound.created` | 库存管理 | 工程、项目管理 | 回写工程领料和项目成本 |
| `purchase.order.received` | 库存管理 | 财务、供应链采购 | 到货后可付款和评价 |
| `engineering.accepted` | 工程管理 | 项目、财务、培训 | 验收后结算、培训、归档 |
| `payment.paid` | 财务管理 | 项目管理、合同管理 | 成本和合同执行回写 |
| `classified.audit.anomaly` | 涉密管理 | 工作台、系统管理 | 异常告警 |

异步事件要求：

1. 事件必须包含业务对象快照。
2. 事件处理必须可重试。
3. 联动任务必须有幂等键。
4. 失败事件必须可查询、可重放、可人工处理。

## 5. 事务边界

### 5.1 单模块事务

以下操作在本模块内完成事务：

1. 新增客户和联系人。
2. 新增工程和施工计划。
3. 新增供应商报价。
4. 库存出入库流水。
5. 财务付款确认。

### 5.2 跨模块事务

跨模块不使用分布式事务，使用事件最终一致性。

示例：库存出库回写项目成本。

```text
库存模块事务：
  1. 写 inventory_records
  2. 写 business_events: inventory.outbound.created
  3. 提交事务

事件处理器：
  1. 读取 inventory.outbound.created
  2. 写 project_costs
  3. 写 event_tasks 幂等记录
```

## 6. 状态联动约束

| 状态 | 只能由谁修改 | 触发条件 |
| --- | --- | --- |
| projects.status | 项目管理 | 立项审批、项目结项 |
| engineering_items.status | 工程管理 | 进场、施工、验收、结算 |
| work_orders.status | 运维管理 | 派工、处理、关闭 |
| purchase_orders.status | 供应链采购管理 | 审批、供应商确认、到货 |
| inventory_records | 库存管理 | 入库、出库、调拨、退料 |
| contracts.status | 合同管理 | 审批、执行、终止、归档 |
| payment_requests.status | 财务管理 | 审批、付款 |
| classified_objects.classification_status | 涉密管理 | 定密、变更、解密 |

## 7. 典型级联关系

### 7.1 工程领料

```text
工程管理创建材料需求
  -> 库存管理生成物料申请
  -> 库存足够：出库
  -> 库存不足：供应链采购询价/竞价
  -> 到货入库或直发现场
  -> 工程现场签收
  -> 工程材料记录更新
  -> 项目成本更新
```

禁止：

1. 工程管理直接减少库存。
2. 供应链采购直接增加库存。
3. 财务直接改物料成本。

### 7.2 工程验收到结算

```text
工程验收通过
  -> 触发 engineering.accepted
  -> 检查退料、变更签证、质量整改
  -> 生成结算草稿
  -> 结算审批
  -> 财务付款或项目成本归集
  -> 工程状态 settled
```

### 7.3 客户商机转项目

```text
客户商机 won
  -> 客户管理触发 opportunity.won
  -> 项目管理创建项目草稿
  -> 项目立项审批
  -> 项目通过后回写商机 project_id
```

## 8. 数据一致性检查任务

建议每天执行一致性检查：

| 检查项 | 规则 |
| --- | --- |
| 工程材料一致性 | 工程材料使用量 <= 签收量 - 退料量 |
| 项目成本一致性 | project_costs 来源单据必须存在 |
| 库存快照一致性 | inventory_snapshots.qty = inventory_records 聚合 |
| 供应商订单一致性 | purchase_order_items 合计 = purchase_orders.total_amount |
| 审批状态一致性 | 业务 approval_status 与 approvals.status 一致 |
| 涉密授权一致性 | classified_objects 有密级时必须有责任人 |

## 9. 一致性检查 API

```text
/api/system/consistency/check.php
```

参数：

```text
type=inventory/project_cost/approval/engineering/supplier/classified/all
```

响应：

```json
{
  "code": 0,
  "data": {
    "type": "inventory",
    "error_count": 3,
    "items": [
      {
        "business_type": "inventory",
        "business_id": 1001,
        "message": "库存快照与流水聚合不一致"
      }
    ]
  }
}
```

## 10. 联动失败人工处理

失败事件进入人工处理页面：

```text
系统管理 -> 日志管理 -> 联动失败任务
```

字段：

| 字段 | 说明 |
| --- | --- |
| 事件类型 | event_type |
| 业务对象 | business_type + business_id |
| 任务类型 | todo/message/cost/update/callback |
| 失败原因 | last_error |
| 重试次数 | retry_count |
| 处理动作 | 重试、忽略、人工完成 |

## 11. 开发约束

1. 模块之间不得互相直接写主表。
2. 所有跨模块写入必须通过事件或明确 API。
3. 成本、库存、审批、付款等关键联动必须有幂等键。
4. 外部账号和第三方分享只允许最小字段集。
5. 涉密事件不得推送正文内容。
6. 工作台只消费事件、待办、消息，不直接处理业务逻辑。
