# 涉密含党支部企业管理系统需求文档

> 本文件由根目录 `需求文档.md` 拆分而来，便于 GitHub 直接预览。完整总览请查看 `../../REQUIREMENTS.md`。

## 8. 功能模块拆解

### 8.1 工作台

1. 首页仪表盘按角色显示不同卡片。
2. 普通用户展示个人待办、通知、审批、打卡、培训、物料和项目反馈。
3. 部门管理员展示部门待办、审批概览、项目进度、人员考勤、库存预警。
4. 系统管理员展示用户、角色、模块、日志、备份、安全告警。
5. 常用功能入口由用户权限决定，只显示可访问功能。

### 8.2 审批管理

1. 审批管理是流程中心，不是业务数据归属地。
2. 费用报销、请假、合同、项目立项等业务单据仍由原业务模块创建和维护。
3. 审批管理只保存审批实例、审批任务、审批意见、节点状态、抄送和流转日志。
4. 支持按业务类型筛选审批任务，用于待办聚合和报表统计。
5. 支持审批流配置、节点审批人、条件分支。
6. 支持审批意见、附件、驳回、撤回、转交、加签、抄送。
7. 支持审批超时提醒和审批日志。

### 8.3 财务报销扩展

费用报销应支持：

1. 单张发票报销。
2. 多张发票合并报销。
3. 项目报销，从项目列表中选择项目。
4. 自定义费用类别，由系统管理员维护。
5. 常见类别：差旅费、交通费、快递费、物业费、办公用品费、招待费、通讯费、培训费、维修费、采购费、其他费用。
6. 附件上传、发票信息、报销明细、审批记录、付款状态。

### 8.4 党建管理

党建管理是独立业务模块，不再只是人事管理下的附属菜单。人事管理负责员工主档案，党建管理负责党组织、党员发展、组织生活、党费、学习和党建台账。

#### 8.4.1 党建核心对象

| 对象 | 说明 | 关键关联 |
| --- | --- | --- |
| 党组织 | 党委、党总支、党支部、党小组 | 关联部门、负责人、上级党组织 |
| 党员 | 党员档案、组织关系、党员状态 | 关联员工档案、用户账号 |
| 发展对象 | 入党申请人、积极分子、发展对象、预备党员 | 关联员工档案、培养联系人 |
| 组织生活 | 三会一课、主题党日、民主生活会、组织生活会 | 关联党组织、参会党员、会议资料 |
| 党费 | 缴费标准、缴费记录、欠缴提醒 | 关联党员、缴费周期 |
| 党建学习 | 学习计划、党建课程、考试记录 | 关联培训资源、培训记录 |
| 党建公告 | 通知、公示、学习安排 | 关联通知公告、阅读反馈 |
| 党建台账 | 制度文件、会议纪要、活动资料、影像资料 | 关联附件、密级、归档目录 |

#### 8.4.2 党建业务流程

1. 人事管理维护员工档案。
2. 党建管理将符合条件的员工登记为党员、入党申请人或培养对象。
3. 党组织管理维护党委、党总支、党支部、党小组及上下级关系。
4. 发展党员流程按入党申请、积极分子、发展对象、预备党员、转正归档流转。
5. 三会一课和主题党日支持计划、通知、签到、纪要、附件和归档。
6. 党费管理按党员、缴费周期、缴费标准生成缴费记录和欠缴提醒。
7. 党建学习调用培训管理中的课程、考试和学习记录，形成党员学习统计。
8. 党建公告通过通知公告模块发布，阅读反馈回写党建统计。
9. 党建台账统一归档会议、活动、制度和学习资料，涉密资料按密级控制。

#### 8.4.3 党建权限规则

1. 普通党员只能查看本人党员档案、本人组织生活、本人学习和党费记录。
2. 支部管理员可维护本支部党员、会议、党费和党建台账。
3. 党委或党务管理员可维护全局党组织和党员发展流程。
4. 涉及组织关系调整、党员状态变更、发展党员关键节点必须记录审批和审计日志。
5. 党建资料如包含涉密内容，应同步进入涉密管理的密级、访问和下载控制。

### 8.5 合同统一元数据

所有合同统一进入合同管理模块，合同类型作为元数据维护：

1. 人事合同
2. 运维合同
3. 采购合同
4. 销售合同
5. 项目合同
6. 服务合同
7. 租赁合同
8. 其他合同

合同可关联客户、项目、供应商、员工、设备、工程、收付款和审批流程。

### 8.6 涉密管理

涉密管理是系统的安全业务模块，不等同于系统管理中的安全设置。系统管理负责账号、权限、日志和参数，涉密管理负责涉密项目、涉密文件、涉密载体、定密审批、借阅外发、保密检查、泄密事件和涉密审计。

#### 8.6.1 涉密核心对象

| 对象 | 说明 | 关键关联 |
| --- | --- | --- |
| 密级规则 | 密级、保密期限、知悉范围、解密条件 | 关联系统字典、审批流程 |
| 涉密项目 | 带密级的项目或专项任务 | 关联项目管理、成员、合同、附件 |
| 涉密文件 | 电子文件、纸质文件、图纸、合同、会议纪要 | 关联附件、项目、合同、党建台账 |
| 涉密载体 | U 盘、移动硬盘、光盘、纸质资料、设备 | 关联领用人、保管人、出入库记录 |
| 定密申请 | 新增定密、变更密级、解密申请 | 关联审批管理 |
| 借阅外发 | 文件借阅、载体借用、外发审批、归还确认 | 关联审批、消息提醒 |
| 保密检查 | 检查计划、检查记录、问题整改、复查 | 关联责任部门和整改人 |
| 保密教育 | 保密课程、考试、承诺书 | 关联培训管理和员工档案 |
| 泄密事件 | 事件登记、等级、处置、整改、追责 | 关联审批、通知、审计 |
| 涉密审计 | 访问、下载、复制、导出、外发、删除尝试 | 关联用户、IP、设备、业务对象 |

#### 8.6.2 涉密业务流程

1. 用户在项目、合同、附件、党建台账等业务中标记涉密属性或发起定密申请。
2. 定密申请进入审批管理，由保密管理员或指定审批人确认密级、知悉范围和保密期限。
3. 定密通过后，业务对象写入 `security_level`、知悉范围、保密期限和解密条件。
4. 用户访问涉密对象时，API 同时校验 RBAC 权限、数据范围、密级授权和知悉范围。
5. 涉密文件下载、预览、复制、导出、外发必须记录审计日志，必要时触发二次审批。
6. 涉密载体领用、借出、归还、销毁必须形成台账和责任人记录。
7. 保密检查发现问题后形成整改任务，进入工作台待办并跟踪闭环。
8. 泄密事件必须登记影响范围、处置过程、整改结果和追责记录。
9. 保密期满或业务结束后，可发起解密申请；解密后仍保留历史密级和访问日志。

#### 8.6.3 涉密访问控制规则

1. **先鉴权，再鉴密**：用户必须先拥有菜单/API 权限，再校验密级授权和知悉范围。
2. **最小知悉范围**：涉密对象默认仅创建人、审批人、责任人和授权成员可见。
3. **密级向上隔离**：低密级授权不能访问高密级对象，高密级用户也不能越权访问非授权对象。
4. **附件单独控权**：业务单据可见不代表附件可下载，附件需要独立校验密级和下载权限。
5. **导出高于查询**：允许查询不等于允许导出，涉密导出必须单独授权或审批。
6. **外发必须审批**：涉密文件、载体、合同、图纸外发必须审批并记录接收方。
7. **全链路审计**：预览、下载、导出、复制、打印、外发、删除尝试均应记录。
8. **异常告警**：短时间大量下载、非工作时间访问、越权尝试、反复失败应生成告警。

### 8.7 协作团队管理

协作团队管理用于统一管理参与工程项目施工、零散项目施工、项目运维、市场开拓等工作的内部团队、外部人员、外聘人员和外部公司。它不是人事管理的替代品，也不是供应链采购管理的替代品。

#### 8.7.1 协作团队核心对象

| 对象 | 说明 | 关键关联 |
| --- | --- | --- |
| 内部团队 | 由企业内部员工组成的施工、运维、市场团队 | 关联人事员工、部门、项目 |
| 外部人员 | 外部个人协作者、临时施工或运维人员 | 关联资质、合同、任务 |
| 外聘人员 | 外聘专家、顾问、临聘人员、劳务人员 | 关联聘用合同、费用标准 |
| 外部公司 | 外包公司、施工队、运维服务商、市场合作公司 | 关联资质、合同、项目、评价 |
| 团队资质 | 人员证书、公司资质、保险、准入记录 | 关联派工准入 |
| 团队任务 | 工程、零散、运维、市场开拓等任务派工 | 关联项目、工程、工单、商机 |
| 执行记录 | 到场、工时、工程量、过程照片、问题反馈 | 关联来源任务 |
| 团队评价 | 质量、时效、安全、服务、客户反馈 | 影响后续派工和评级 |
| 团队结算 | 工时、工程量、费用、结算审批、付款状态 | 关联财务和合同 |

#### 8.7.2 协作团队业务流程

1. 管理员建立团队档案，选择团队类型：内部团队、外部人员、外聘人员、外部公司。
2. 上传或维护资质、证书、保险、服务范围、费用标准和准入状态。
3. 项目、工程、运维、客户商机等模块发起团队需求。
4. 协作团队管理根据技能、区域、资质、可用状态和历史评价推荐团队。
5. 部门管理员或项目负责人发起团队派工，必要时进入审批。
6. 团队执行任务，提交到场、工时、工程量、照片、问题和反馈。
7. 来源模块同步查看执行结果，工程进度、运维工单或市场拜访状态随之更新。
8. 任务完成后进行质量评价、安全评价、客户评价和履约评价。
9. 产生费用时进入结算管理，结算审批通过后进入财务付款。

#### 8.7.3 协作团队边界规则

1. 内部人员基础档案归人事管理，协作团队只保存技能、可派工状态和任务记录。
2. 外部公司如果主要提供人员和服务执行，归协作团队管理；如果主要提供商品和供货，归供应链采购管理。
3. 工程和运维模块负责业务过程，协作团队管理负责执行主体、资质、评价和结算。
4. 团队结算可关联合同和财务付款，但合同正文归合同管理，付款归财务管理。
5. 涉密项目派工必须同时校验团队成员涉密授权和知悉范围。

### 8.8 供应链采购管理

供应链采购管理用于统一管理供应商入驻、供应商后台、商品目录、询价竞价、报价比选、一键下单、履约评价。它解决“向谁买、买什么、谁报价、如何比价、如何下单”的问题；库存管理解决“物料如何入库、出库、盘点和签收”的问题。

#### 8.8.1 供应商核心对象

| 对象 | 说明 | 关键关联 |
| --- | --- | --- |
| 供应商 | 企业供应商或个体供应商 | 关联入驻审批、资质、等级 |
| 供应商账号 | 供应商后台登录账号 | 关联供应商和权限 |
| 商品 | 供应商可供商品、规格、参数、价格、库存 | 关联物料档案和询价 |
| 入驻申请 | 自主申请、注册后审批、后台添加 | 关联审批管理 |
| 询价单 | 平台按项目参数、物料清单发起询价 | 关联项目、工程、工单、库存采购申请 |
| 竞价单 | 多供应商报价和竞价轮次 | 关联询价单和报价 |
| 报价单 | 供应商对部分或全部商品的价格、交期、税率、运费 | 关联商品和供应商 |
| 比价清单 | 平台按规则提取最低价或最优组合 | 关联多个供应商和多个商品 |
| 采购订单 | 一键下单生成的供应商拆单 | 关联审批、库存、财务 |
| 履约记录 | 发货、到货、质量、服务、违约 | 影响供应商评级 |

#### 8.8.2 供应商业务流程

1. 供应商通过申请加入、注册后审批或后台添加进入系统。
2. 后台审核供应商资质、经营范围、联系人、账号和状态。
3. 审核通过后，供应商可进入供应商后台维护商品、规格参数、价格、库存和交期。
4. 项目、工程、运维或库存发起物料需求，形成询价单。
5. 平台选择供应商范围和商品范围，发起询价或竞价。
6. 供应商可对全部商品报价，也可只对部分可供商品报价。
7. 平台汇总已报价供应商，按最低价、交期、质量等级、历史履约等规则生成比价清单。
8. 比价清单可以包含多家供应商和多种商品，形成最优组合采购方案。
9. 平台一键下单后，按供应商拆分采购订单，并进入采购审批。
10. 审批通过后，各供应商收到采购通知，按要求时限和地址供货。
11. 到货后库存管理办理到货、验收、入库或签收。
12. 财务管理根据订单、合同、入库或签收结果办理应付和付款。
13. 平台根据价格、交期、质量、服务和违约情况形成供应商履约评价。

#### 8.8.3 供应商比价和下单规则

1. 报价可覆盖全部商品，也可覆盖部分商品；未报价商品不参与该供应商比价。
2. 默认比价规则为同等参数下取最低有效报价，可扩展为综合评分规则。
3. 最优报价清单允许同一采购需求拆分给多家供应商。
4. 一键下单前必须校验预算、项目、采购权限、供应商状态、报价有效期和库存需求。
5. 一键下单后必须进入审批；审批通过前不通知供应商正式供货。
6. 审批通过后生成供应商拆单，供应商只能查看自己的订单和商品。
7. 订单到货和签收结果回写库存，付款状态回写财务和供应商履约。
8. 涉密项目采购时，供应商和商品信息应按涉密规则控制知悉范围。

### 8.9 模块边界与主责

| 模块 | 主责 | 不应承担的职责 | 关键关联 |
| --- | --- | --- | --- |
| 工作台 | 聚合待办、消息、快捷入口和个人数据看板 | 不保存业务单据主数据 | 审批、通知、项目、工单、培训 |
| 审批管理 | 流程定义、审批实例、审批任务、审批日志 | 不替代财务、人事、合同、项目等业务模块 | 所有需要审批的业务单据 |
| 项目管理 | 项目立项、计划、任务、资源、成本、文档、报告 | 不直接管理库存实物、供应商报价和财务凭证 | 客户、合同、工程、协作团队、供应商、库存、财务 |
| 客户管理 | 客户档案、联系人、拜访、商机、客户分析 | 不作为合同归档和项目执行主模块 | 项目、合同管理、通知 |
| 人事管理 | 组织、员工、考勤、薪酬、绩效、员工培训记录、党务关联基础 | 不直接管理课程资源、考试题库和党建业务台账 | 培训、党建、审批、合同 |
| 财务管理 | 报销、付款、借款、还款、应收应付、预算、资产、报表 | 不创建项目任务和库存出入库 | 项目、合同、库存、审批 |
| 运维管理 | 设备、计划、巡检、工单、安全事件 | 不直接承担工程施工全过程，不维护外部团队档案 | 设备、协作团队、库存、财务、通知 |
| 工程管理 | 工程或零散施工过程、验收、交付培训 | 不替代项目立项、团队档案和合同归档 | 项目、协作团队、库存、培训、合同 |
| 协作团队管理 | 内部团队、外部人员、外聘人员、外部公司、资质、派工、评价、结算 | 不替代人事员工主档案、供应商商品报价、工程过程管理 | 人事、项目、工程、运维、客户、合同、财务 |
| 合同管理 | 合同模板、起草、审批、执行、归档、查询、风险分析 | 不替代客户、员工、供应商和协作团队主数据 | 客户、项目、财务、人事、运维、供应商、协作团队 |
| 供应链采购管理 | 供应商入驻、商品目录、询价竞价、报价、比价、采购下单、履约评价 | 不替代库存出入库、财务付款和合同归档 | 库存、项目、工程、运维、合同、财务、审批 |
| 库存管理 | 物料档案、采购申请、入库、出库、调拨、盘点、库存预警 | 不维护供应商商品报价和供应商等级 | 项目、工程、运维、供应商、财务 |
| 培训管理 | 通用课程资源、计划、学习、考试、证书、培训统计 | 不维护员工主档案，不直接承载党建或保密业务台账 | 人事、党建、涉密、工程验收 |
| 通知公告 | 通知公告发布、反馈、阅读统计、消息模板、订阅策略 | 不保存业务单据状态，不单独设置党建公告业务台账 | 工作台、审批、培训、党建 |
| 系统管理 | 用户、角色、权限、菜单、日志、备份、参数、安全 | 不处理日常业务单据 | 全系统 |
| 涉密管理 | 密级、涉密项目、涉密文件、涉密载体、定密审批、借阅外发、保密检查、涉密审计 | 不替代系统账号权限和业务模块主数据 | 系统管理、项目、合同、附件、党建、审批 |
| 党建管理 | 党组织、党员、发展党员、组织生活、党费、党建学习、党建台账 | 不替代员工主档案和培训课程资源 | 人事、培训、通知公告、涉密管理 |

### 8.10 跨模块关联矩阵

| 主对象 | 来源模块 | 关联模块 | 关联说明 |
| --- | --- | --- | --- |
| 用户 | 系统管理 | 人事管理、审批管理、日志管理 | 用户绑定员工档案后参与审批、考勤和审计 |

### 8.11 关键业务链路

#### 8.11.1 客户商机到项目交付

1. 客户管理维护客户档案、联系人和拜访记录。
2. 商机成熟后发起项目立项申请。
3. 项目管理创建项目，进入立项审批。
4. 立项通过后生成项目编号、项目计划、任务和预算。
5. 合同管理根据客户和项目起草销售或服务合同。
6. 合同送审通过后进入合同执行，关联收付款计划。
7. 工程管理根据项目创建工程或零散任务。
8. 协作团队管理根据工程、运维或市场任务派发内部团队、外部人员、外聘人员或外部公司。
9. 库存管理根据项目或工程办理物料申请；需要供应商报价时进入供应商询价或竞价。
10. 供应链采购管理形成比价清单并完成采购下单审批。
11. 财务管理处理项目报销、付款申请、应收应付和成本归集。
12. 工程验收后触发培训计划、项目报告和项目归档。

#### 8.11.2 财务报销与项目成本

1. 用户在财务管理创建费用报销单。
2. 如为项目报销，必须选择项目；如与工程相关，可进一步选择工程。
3. 报销单可上传一张或多张发票和附件。
4. 报销单提交后，审批管理生成审批实例。
5. 审批通过后，财务确认付款或入账状态。
6. 已入账金额回写项目成本，但不得反向修改原始报销单。
7. 项目管理通过成本汇总查看预算、实际成本和差异。

#### 8.11.3 合同全生命周期

1. 合同可从客户、项目、人事、运维、采购等模块发起，也可在合同管理直接起草。
2. 合同管理统一保存合同正文、模板、类型、相对方、金额、期限、密级和附件。
3. 合同提交审批后，审批管理只记录流程，不复制合同正文。
4. 合同送审通过后进入执行状态，并生成履约、收款、付款、到期提醒。
5. 财务管理根据合同执行节点处理应收应付。
6. 合同终止、续签、变更均形成合同变更记录并保留审计轨迹。

#### 8.11.4 物料申请到库存闭环

1. 项目、工程或运维工单提出物料需求。
2. 库存管理创建物料申请，并绑定来源类型和来源单据。
3. 需要采购时，库存管理生成采购需求并传递给供应链采购管理。
4. 供应链采购管理发起询价或竞价，供应商按商品部分或全部报价。
5. 平台生成比价清单并一键下单，采购订单审批通过后通知供应商供货。
6. 供应商按供货时限和地址发货。
7. 到货后库存管理办理验收、入库、出库或签收。
8. 到货、发货、签收形成库存流水。
9. 库存变化触发实时库存、库存预警和库存分析。

#### 8.11.5 协作团队任务执行闭环

1. 项目、工程、运维或客户商机产生团队需求。
2. 协作团队管理根据任务类型、区域、技能、资质、可用状态和历史评价筛选团队。
3. 内部团队从员工中引用人员，外部人员、外聘人员和外部公司从协作团队档案中选择。
4. 派工需要审批时，审批管理生成审批任务。
5. 派工通过后，团队成员接收任务，提交到场、工时、工程量、照片和问题反馈。
6. 来源模块同步查看执行记录，并更新工程进度、运维工单状态或市场开拓进度。
7. 任务完成后进行质量、安全、时效、客户满意度评价。
8. 如产生费用，协作团队管理生成结算单，审批通过后进入财务付款。

#### 8.11.6 供应商竞价采购闭环

1. 项目、工程、运维或库存提出物料采购需求。
2. 供应链采购管理根据物料参数、数量、收货地址、时限生成询价或竞价批次。
3. 供应商通过供应商后台查看询价内容，可对部分商品或全部商品报价。
4. 平台汇总有效报价，按最低价或综合评分生成比价清单。
5. 比价清单可包含多家供应商和多种商品，形成组合采购方案。
6. 平台一键下单后生成采购订单和供应商拆单，并提交审批。
7. 审批通过后供应商收到采购通知，按要求发货。
8. 库存管理办理到货、验收、入库、签收。
9. 财务管理根据合同、订单、入库或签收结果处理应付和付款。
10. 供应链采购管理沉淀履约评价，影响后续报价排名和准入等级。

#### 8.11.7 人事党建与培训联动

1. 人事管理维护员工档案、组织架构和岗位。
2. 党建管理在员工档案基础上维护党员信息和党支部关系。
3. 党支部发布三会一课、党费、党建活动和学习要求。
4. 党建课程在培训管理中作为课程分类管理。
5. 党员学习记录、考试成绩和证书回写培训记录，并可在党建统计中汇总。
6. 党建公告通过通知公告模块发布，阅读反馈进入统计。

#### 8.11.8 运维工单到安全事件

1. 运维管理维护设备台账和巡检计划。
2. 巡检发现问题后生成工单或特殊事件报告。
3. 工单派发给处理人，处理过程中可申请备件或费用。
4. 备件领用进入库存出库，费用进入财务管理并发起审批任务。
5. 安全事件需要记录事件等级、处理过程、整改闭环和附件。
6. 完成后进入运维报表，并同步工作台消息。

#### 8.11.9 涉密对象全生命周期

1. 业务模块创建项目、合同、文件、党建台账或工程资料。
2. 创建人标记涉密属性或发起定密申请。
3. 涉密管理生成定密审批，审批通过后写入密级、保密期限、知悉范围。
4. 用户访问涉密对象时，API 同时校验业务权限、数据范围、密级授权和知悉范围。
5. 借阅、外发、下载、导出、复制、打印等高风险操作进入审批或二次确认。
6. 使用过程持续记录涉密审计日志和异常告警。
7. 保密期满、项目结束或合同终止后发起解密或销毁流程。
8. 解密或销毁完成后归档，历史密级和审计日志永久保留或按保密制度保存。

#### 8.11.10 党建管理闭环

1. 人事管理维护员工档案和部门岗位。
2. 党建管理建立党组织架构，并把员工关联为党员、申请人或培养对象。
3. 发展党员流程按申请、积极分子、发展对象、预备党员、转正流转。
4. 党组织发布三会一课、主题党日和民主评议安排。
5. 通知公告推送活动通知，工作台生成待办和消息。
6. 党员签到、学习、考试、党费缴纳和资料提交形成党建台账。
7. 涉密党建资料进入涉密管理，按密级控制访问和下载。
8. 党建报表按党组织、党员状态、学习情况、党费、活动参与度统计。

### 8.12 单据状态与数据一致性

所有业务单据应统一状态模型，避免每个模块自行定义互相冲突的状态。

| 状态 | 含义 | 适用说明 |
| --- | --- | --- |
| draft | 草稿 | 用户创建但未提交 |
| submitted | 已提交 | 已进入审批或业务处理 |
| approving | 审批中 | 审批实例未完成 |
| rejected | 已驳回 | 可修改后重新提交或关闭 |
| approved | 已审批 | 审批通过，等待业务执行 |
| processing | 执行中 | 工程、工单、合同、培训等正在执行 |
| completed | 已完成 | 业务闭环 |
| cancelled | 已取消 | 用户或管理员按规则取消 |
| archived | 已归档 | 完成后进入档案或历史 |

一致性规则：

1. 审批结果只能改变业务单据的审批状态，不能绕过业务模块直接修改业务明细。
2. 业务模块保存单据主表和明细表，审批管理保存流程实例和任务。
3. 附件统一由附件服务管理，业务模块只保存附件关联关系。
4. 所有业务单据必须保存来源模块、来源单据、创建人、所属部门和密级字段。
5. 跨模块回写必须记录日志，例如报销入账回写项目成本、库存出库回写工程领料。

### 8.13 菜单与业务能力的关系

菜单只是入口，不等于业务能力。后续开发时按以下规则拆分：

1. 一个业务能力可以被多个菜单入口调用，例如“费用报销”既可从工作台快捷入口进入，也可从财务管理进入。
2. 一个业务单据只能有一个主归属模块，例如报销单归属财务管理，审批中心只展示它的审批任务。
3. 普通用户、部门管理员看到的菜单不同，但调用的底层 API 应保持一致，由权限和数据范围控制结果。
4. 工作台所有数量、待办和快捷入口均来自 API 聚合，不在页面写死。
5. 二级菜单不足以表达复杂页面时，可在页面内部使用页签、筛选或步骤条实现，不额外膨胀主菜单。

### 8.14 客户管理专项：摧龙六式客户经营模型

客户管理采用“摧龙六式”思想进行设计，面向大客户和长期客户经营。这里的“摧龙六式”按销售经营流程落地为：客户分析、建立信任、挖掘需求、呈现价值、赢取承诺、回收账款。系统不只记录客户名称和联系人，还要沉淀客户关系、拜访过程、商务活动、机会线索、竞争情况、合同履约和交接资料。

#### 8.14.1 六式与系统数据

| 六式阶段 | 系统记录内容 | 目标 |
| --- | --- | --- |
| 客户分析 | 企业档案、组织结构、关键部门、决策链、联系人画像、现有供应商、竞争对手、历史合同 | 让销售和接任者快速理解客户全貌 |
| 建立信任 | 向导/内线、关系等级、互动记录、信任事件、合规商务活动、客户偏好 | 判断关系深度，避免只凭个人记忆跟进 |
| 挖掘需求 | 显性需求、潜在痛点、预算、采购计划、决策标准、紧急程度、影响部门 | 找到真实需求和项目机会 |
| 呈现价值 | 方案建议、产品价值、案例、ROI、风险消除措施、竞争差异 | 形成可追踪的方案沟通记录 |
| 赢取承诺 | 下一步动作、会议纪要、试点承诺、立项承诺、招采节点、合同推进 | 明确客户承诺和销售阶段 |
| 回收账款 | 合同、交付、验收、发票、回款计划、逾期风险、满意度 | 将销售闭环延伸到回款和复购 |

#### 8.14.2 客户档案详细内容

1. 企业基础信息：客户名称、统一社会信用代码、性质、行业、规模、地址、官网、经营范围、主营业务、关联企业。
2. 经营与业务现状：当前业务痛点、现有系统或产品使用情况、现有供应商、采购周期、预算习惯、历史采购记录。
3. 组织结构：部门、岗位、汇报关系、采购相关部门、使用部门、技术部门、财务部门、决策层。
4. 决策链：发起人、使用者、技术把关人、财务影响人、采购执行人、决策人、反对者、支持者、向导。
5. 联系人画像：姓名、职务、角色、影响力、联系方式、性格特点、沟通偏好、兴趣爱好、生日、家庭情况、社会关系、禁忌事项、合规备注。
6. 竞争信息：竞争对手、竞争产品、竞争优势、竞争关系人、历史输赢原因、价格策略、客户倾向。
7. 风险信息：关系风险、预算风险、竞争风险、交付风险、回款风险、合规风险。
8. 历史沉淀：拜访记录、商务活动、商机、项目、合同、回款、服务投诉、满意度、交接记录。

> 合规要求：联系人画像中的家庭情况、社会关系、喜好等信息只能用于合法合规的客户服务和沟通，不得记录违法违规、公序良俗风险或侵犯隐私的信息；敏感内容应按权限查看并记录访问日志。

#### 8.14.3 拜访与商务活动记录

每次客户拜访应至少记录：

1. 拜访时间、地点、拜访方式、参与人员。
2. 被拜访人姓名、职务、角色、联系方式。
3. 拜访主题、沟通内容、客户反馈、客户情绪和关注点。
4. 取得效果：建立关系、发现需求、推进立项、获得承诺、解决异议、促成合同等。
5. 下一步动作、责任人、计划时间、提醒方式。
6. 附件：会议纪要、照片、资料、方案、客户提供材料。

商务活动应记录：

1. 活动类型、活动目的、参与人员、活动时间和地点。
2. 投入内容、费用、合规审批、关联客户和联系人。
3. 活动效果、客户反馈、后续动作。
4. 是否产生商机、项目、合同或关系等级变化。

#### 8.14.4 客户交接包

当客户负责人离职、调岗或客户转交时，系统必须生成客户交接包：

1. 客户概览：客户等级、经营情况、当前阶段、负责人、协同人员。
2. 关键联系人：决策人、影响人、使用人、采购人、向导、反对者及关系状态。
3. 最近动态：最近拜访、最近商务活动、未完成待办、客户反馈。
4. 商机和项目：正在推进的商机、项目、预计金额、当前障碍、下一步动作。
5. 合同和回款：历史合同、在执行合同、应收款、回款风险。
6. 竞争和风险：竞争对手、客户倾向、关系断点、合规风险。
7. 接任建议：优先拜访对象、沟通策略、注意事项、预计突破点。

交接完成后，接任人应确认交接，系统记录确认时间和交接意见。

### 8.15 运维管理专项细化

运维管理围绕“设备-计划-巡检-工单-派工-备件-验收-复盘”闭环设计。

#### 8.15.1 运维对象

| 对象 | 说明 | 关键关联 |
| --- | --- | --- |
| 设备 | 企业设备、项目设备、客户现场设备 | 合同、项目、工程、供应链采购 |
| 运维计划 | 周期性保养、巡检、维护计划 | 设备、团队、工单 |
| 巡检记录 | 巡检点、巡检项、异常、照片 | 工单、安全事件 |
| 工单 | 报修、维护、巡检异常、客户服务请求 | 协作团队、备件、财务 |
| SLA | 响应时限、处理时限、服务等级 | 合同、客户、工单 |
| 备件 | 工单使用备件、旧件处理 | 库存管理 |
| 知识库 | 故障原因、处理方案、标准作业 | 工单复盘 |

#### 8.15.2 运维流程

1. 设备台账登记设备、位置、责任人、质保期、合同和状态。
2. 运维计划按设备、客户、合同或项目生成巡检任务。
3. 巡检发现异常后生成工单，或由客户报修直接生成工单。
4. 工单根据技能、区域、SLA 和可用状态派发给内部人员或协作团队。
5. 处理过程中可申请备件，库存管理办理出库和签收。
6. 处理人提交过程、照片、备件、更换记录和处理结果。
7. 申请人或管理员验收关闭工单。
8. 工单复盘沉淀到知识库，形成故障统计和 SLA 报表。

### 8.16 工程管理专项细化

工程管理围绕“项目来源-施工计划-团队材料-过程日志-质量安全-变更签证-验收交付”闭环设计，覆盖正式工程和零散工程。

#### 8.16.1 工程对象

| 对象 | 说明 | 关键关联 |
| --- | --- | --- |
| 工程 | 从项目立项创建的工程或零散工程 | 项目、客户、合同 |
| 施工计划 | 施工范围、节点、人员、材料、设备、风险 | 协作团队、库存 |
| 施工日志 | 每日施工内容、人员、材料、问题 | 过程追溯 |
| 材料设备 | 工程材料申请、到货、领用、签收、退料 | 库存、供应链采购 |
| 质量安全 | 质量检查、安全交底、整改闭环 | 协作团队、审批 |
| 变更签证 | 范围、费用、工期、原因、审批状态 | 合同、项目成本 |
| 验收交付 | 验收项、交付资料、培训、归档 | 培训、附件、涉密 |

#### 8.16.2 工程流程

1. 项目立项通过后，根据项目内容创建工程；临时小任务创建为零散工程。
2. 编制施工计划，明确范围、节点、负责人、协作团队、材料设备和风险预案。
3. 材料需求进入库存采购申请；需要供应商报价时进入供应链采购管理。
4. 施工过程按节点提交施工日志、照片、问题、整改和进度。
5. 质量安全检查发现问题后形成整改任务，必要时进入审批。
6. 范围、费用或工期变化时创建变更签证，审批通过后回写项目成本和合同执行。
7. 工程完成后进行验收，生成验收记录、交付资料和培训计划。
8. 验收通过后归档资料，涉密资料进入涉密管理控制。
