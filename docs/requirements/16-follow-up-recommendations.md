# 涉密含党支部企业管理系统需求文档

> 本文件由根目录 `需求文档.md` 拆分而来，便于 GitHub 直接预览。完整总览请查看 `../../REQUIREMENTS.md`。

## 16. 后续开发建议

1. 先落地 RBAC、数据权限、动态菜单和统一 API 基础能力，再开发业务模块。
2. 先建立组织、员工、党组织、客户、项目、合同、物料、设备、协作团队、供应商、商品、密级规则等主数据，再开发跨模块流程。
3. 审批、附件、待办、消息、日志应作为公共能力复用，避免每个模块重复实现。
4. 业务模块统一使用列表、详情、表单、审批、附件、日志、状态流转模式。
5. 党建管理应以员工档案为人员基础，避免重复维护人员主数据。
6. 涉密管理应作为横切控制能力接入项目、合同、附件、党建台账等模块。
7. 协作团队管理应作为项目、工程、运维和市场任务的执行主体管理模块，不替代具体业务过程。
8. 供应链采购管理应作为商品、报价、竞价和履约评价中心，不替代库存入出库和财务付款。
9. 涉密生产部署前，需要确认是否允许公网 CDN、短信网关和外部资源访问。
10. 如必须在涉密内网运行，建议同步建设本地静态资源镜像、内网短信服务和统一身份认证。
