# 涉密含党支部企业管理系统需求文档

> 本文件由根目录 `需求文档.md` 拆分而来，便于 GitHub 直接预览。完整总览请查看 `../../REQUIREMENTS.md`。

## 3. 用户与角色

### 3.1 默认账号

| 账号 | 默认角色 | 权限说明 |
| --- | --- | --- |
| admin | 系统管理员 | 拥有全部菜单、全部模块、全部数据和系统配置权限 |
| dpt1 | 部门管理员 | 根据系统管理员授权使用指定模块，可管理本部门或授权范围内数据 |
| user1 | 普通用户 | 根据系统管理员授权使用指定模块，只能访问本人或被授权数据 |

> 默认密码应在初始化脚本中生成强密码或首次登录强制修改，不建议在文档和代码中明文固化弱密码。

### 3.2 默认角色组

1. 系统管理员
2. 部门管理员
3. 普通用户

### 3.3 扩展账号类型

默认角色组仍为系统管理员、部门管理员、普通用户三类内部账号。随着协作团队管理和供应链采购管理落地，需要增加受限外部账号类型：

| 账号类型 | 适用对象 | 权限边界 |
| --- | --- | --- |
| 供应商账号 | 已入驻或待审核供应商 | 只能维护本供应商资料、商品、报价、订单反馈和履约资料 |
| 外部协作账号 | 外部人员、外聘人员、外部公司指定联系人 | 只能查看本人或本团队派工任务、提交执行记录和反馈 |
| 临时访客账号 | 临时参与验收、培训、外部协同的人员 | 仅在有效期内访问指定业务或资料 |

外部账号必须独立标识账号类型、所属供应商或协作团队、有效期、状态和可访问范围，不应默认拥有内部普通用户菜单。

### 3.4 权限原则

1. 系统管理员默认拥有全部权限。
2. 部门管理员和普通用户不直接绑定固定菜单，而是通过角色授权获得模块和菜单。
3. 菜单显示必须由服务端返回的权限结果决定，前端只负责渲染。
4. API 必须再次校验权限，不能只依赖前端隐藏菜单。
5. 部门管理员默认数据范围为本部门，可由系统管理员扩展为多部门或指定项目。
6. 普通用户默认数据范围为本人，可扩展为本人参与项目、本人提交单据、本人被抄送内容。
