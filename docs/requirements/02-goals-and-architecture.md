# 涉密含党支部企业管理系统需求文档

> 本文件由根目录 `需求文档.md` 拆分而来，便于 GitHub 直接预览。完整总览请查看 `../../REQUIREMENTS.md`。

## 2. 项目目标

### 2.1 建设目标

1. 建设统一风格的 PC 端后台管理系统。
2. 使用 RBAC 权限模型控制用户、角色、模块、菜单和数据范围。
3. 根据登录用户权限动态显示主菜单与二级菜单。
4. 所有业务数据通过 `/api` 路径下的 PHP API 获取，不在网页中写入测试数据。
5. 支持注册、登录、找回密码验证码校验。
6. 支持系统管理员维护模块、菜单、角色、权限和系统配置。
7. 支持党支部、党建管理、党建学习、党建公告等党务业务场景。
8. 支持实时无刷新交互，减少整页刷新，提高后台使用体验。
9. 面向涉密使用场景，补充访问控制、审计、数据安全和部署安全要求。

### 2.2 技术约束

| 项目 | 要求 |
| --- | --- |
| 开发方式 | HTML + PHP + Bootstrap 原生开发 |
| 前端资源 | CSS 和 JS 统一从 bootcdn 引入 |
| 数据库 | MySQL，数据库名 `lz` |
| 数据库地址 | `127.0.0.1` |
| 数据库账号 | `root` |
| 数据库密码 | `rootroot` |
| API 路径 | 所有接口统一放在 `/api` |
| 菜单权限 | RBAC 动态菜单 |
| 页面交互 | 实时无刷新技术 |

> 涉密系统风险提示：如果系统部署在严格涉密或内网隔离环境，直接加载公网 bootcdn 资源会带来外联风险、可用性风险和供应链风险。建议生产涉密环境使用 bootcdn 资源的内网镜像或本地合规资源仓库；如必须严格遵循“资源来自 bootcdn”的要求，应将系统定位为非隔离演示环境或受控专网环境。

### 2.3 本轮迭代修正的问题

原始需求覆盖面很广，但如果直接按菜单开发，会产生以下逻辑问题：

1. **审批与业务模块边界混乱**：费用报销、合同审批、项目立项、人事请假既出现在业务模块中，又出现在审批管理中。修正后，业务单据归属原业务模块，审批管理只作为流程引擎和待办入口。
2. **项目、工程、合同、库存之间缺少主线**：项目立项后会产生合同、工程、物料、成本、验收和培训等后续事项。修正后，以项目为业务主线，工程、合同、库存、财务均通过项目编号或工程编号关联。
3. **通知公告与系统消息混用**：公告是主动发布的信息，消息是业务事件触发的提醒。修正后，通知公告模块负责内容发布，消息提醒由各业务模块触发并进入工作台。
4. **党建与人事、培训、公告关系不清**：党建不是孤立模块，党员来自员工档案，党建学习依托培训资源，党建通知依托通知公告。修正后，党建管理升级为独立业务模块，并与人事、培训、通知公告形成业务关联。
5. **系统管理可能被误用为业务入口**：系统管理只维护用户、权限、菜单、参数、日志和备份，不承载日常业务单据。
6. **权限只描述菜单显示不够**：涉密系统必须同时控制菜单、操作、数据范围、附件、导出和审计，不能只做前端动态菜单。

### 2.4 修正后的总体业务架构

系统按“基础主数据、流程协同、业务执行、支撑治理”四层组织：

| 层级 | 包含模块 | 职责 |
| --- | --- | --- |
| 基础主数据层 | 系统管理、人事管理、客户管理、合同元数据、物料档案、设备台账 | 提供组织、人员、客户、物料、设备、合同类型、字典等基础数据 |
| 流程协同层 | 审批管理、工作台、通知公告、在线会议 | 提供待办、审批、通知、消息、协作和反馈能力 |
| 业务执行层 | 项目管理、工程管理、运维管理、协作团队管理、供应链采购管理、库存管理、财务管理、合同管理、培训管理、党建管理、涉密管理 | 承载企业实际业务过程和业务单据 |
| 支撑治理层 | 权限管理、日志管理、数据备份、安全设置、报表看板 | 提供权限、安全、审计、备份、统计和运营治理能力 |

### 2.5 核心业务主线

系统不是简单菜单集合，而是围绕以下主线协同：

1. **客户到项目主线**：客户档案 -> 商机跟进 -> 项目立项 -> 项目计划 -> 合同起草与送审 -> 项目执行。
2. **项目到工程主线**：项目立项 -> 工程或零散任务创建 -> 过程跟踪 -> 物料申请 -> 工程验收 -> 培训交付 -> 项目归档。
3. **项目到财务主线**：项目预算 -> 成本发生 -> 费用报销 -> 付款申请 -> 应收应付 -> 财务报表。
4. **合同到履约主线**：合同起草 -> 合同送审 -> 合同执行 -> 履约提醒 -> 收付款关联 -> 到期归档。
5. **运维到工单主线**：设备台账 -> 运维计划 -> 巡检记录 -> 工单派发 -> 备件领用 -> 工单验收 -> 安全事件归档。
6. **人事到党建主线**：员工档案 -> 党员信息 -> 党支部管理 -> 三会一课 -> 党费管理 -> 党建学习与公告。
7. **培训到证书主线**：培训资源 -> 培训计划 -> 在线学习 -> 在线考试 -> 成绩记录 -> 证书获取。
8. **涉密业务主线**：定密申请 -> 密级审批 -> 涉密载体登记 -> 借阅/外发/复制审批 -> 使用过程审计 -> 解密/销毁归档。
9. **协作团队到任务执行主线**：团队档案 -> 资质审核 -> 项目/工程/运维/市场任务分派 -> 到场/执行记录 -> 质量评价 -> 费用结算。
10. **供应链采购履约主线**：供应商入驻 -> 商品上架 -> 平台询价/竞价 -> 报价比选 -> 最优报价清单 -> 采购审批 -> 一键下单 -> 发货到货 -> 入库/签收 -> 付款。

### 2.6 菜单去重原则

为避免同一业务在多个模块重复建设，菜单按以下原则保留：

1. **业务单据只归属一个主模块**：费用报销归属财务管理，合同归属合同管理，党员资料归属党建管理，涉密对象归属涉密管理。
2. **审批管理只做流程聚合**：审批管理不再设置“财务审批、人事审批、业务审批”等业务菜单，只保留待办、已办、抄送、流程配置和报表。
3. **工作台只做快捷入口和聚合**：工作台可以展示待办、消息和快捷入口，但不保存业务数据。
4. **通知公告只做发布通道**：党建公告、培训通知、审批提醒等业务消息可使用通知公告能力，但业务栏目保留在对应业务模块。
5. **培训管理只做通用培训能力**：党建学习和保密教育可以调用培训资源、考试和记录，但业务管理入口分别保留在党建管理和涉密管理。
6. **人事管理只维护员工主数据**：党员信息、党组织和党建台账归属党建管理；人事只保留员工与党务身份的引用关系。
7. **合同统一归口合同管理**：客户、项目、采购、人事、运维等模块只展示合同关联视图，不设置独立合同管理入口。
8. **涉密管理是横切控制模块**：项目、合同、附件、党建台账等可标记涉密，但密级、授权、审计、外发、解密统一归涉密管理。
9. **协作团队统一归口协作团队管理**：内部人员、外部人员、外聘人员、外部公司参与施工、运维和市场任务时，人员/公司档案、资质、评价、结算归协作团队管理；具体项目进度仍归项目、工程或运维模块。
10. **供应商和采购协同统一归口供应链采购管理**：供应商入驻、商品、报价、竞价、供应商评价、采购下单归供应链采购管理；库存只负责采购申请、入库、出库和库存流水；财务只负责付款和账务。

### 2.7 重复菜单处理清单

| 原重复项 | 重复原因 | 处理方式 |
| --- | --- | --- |
| 审批管理：财务审批、人事审批、业务审批 | 与财务、人事、合同、项目等业务模块重复 | 删除业务分类菜单，改为审批中心按业务类型筛选 |
| 客户管理：销售合同 | 与合同管理重复 | 改为“客户合同关联”，只展示客户相关合同摘要 |
| 人事管理：培训管理 | 与培训管理重复 | 改为“员工成长档案”，只引用培训记录和证书 |
| 培训管理：党建培训 | 与党建管理重复 | 删除独立党建培训入口，党建学习在党建管理中发起，培训管理提供课程和考试能力 |
| 通知公告：党建公告 | 与党建管理重复 | 删除通知公告中的党建公告入口，党建公告在党建管理中发起并调用通知公告发布能力 |
| 合同管理：合同审批 | 与审批管理重复 | 改为“合同流程”，展示合同送审、审批状态和流转记录，不作为审批中心替代 |
| 涉密管理：保密培训 | 与培训管理重复 | 改为“保密教育”，管理保密承诺、达标要求和学习结果，课程资源复用培训管理 |
| 工作台：常用功能入口 | 与所有业务模块入口重复 | 保留为快捷入口，不作为独立业务归属 |
| 库存管理：物料采购与供应商报价 | 库存负责实物流转，供应链采购负责报价和商品 | 库存保留采购申请、入库、出库；供应链采购管理新增商品、询价、竞价、报价比选、一键下单 |
| 项目/工程/运维中的施工队伍管理 | 与协作团队档案、资质、评价重复 | 项目/工程/运维只引用团队并记录任务执行，团队档案和评价归协作团队管理 |

### 2.8 新增模块命名与边界

#### 2.8.1 协作团队管理命名建议

本模块建议命名为 **协作团队管理**，别名可标注为“外包/外协/团队管理”。原因如下：

1. “外包管理”偏向外部承包，无法覆盖内部人员组成的施工、运维和市场团队。
2. “团队管理”范围过大，容易与组织架构、部门管理、项目成员管理混淆。
3. “协作团队管理”可以同时覆盖内部人员、外部人员、外聘人员和外部公司，并强调这些主体参与项目、工程、运维和市场开拓的协作属性。

协作团队管理的主责是管理“谁可以参与执行任务、具备什么资质、被派到哪里、执行效果如何、如何评价和结算”。项目、工程、运维、客户模块只引用协作团队，不重复维护团队档案。

#### 2.8.2 供应链采购管理命名与边界

本模块建议命名为 **供应链采购管理**，不建议继续只叫“供应商管理”。原因如下：

1. “供应商管理”偏向供应商档案和资质维护，无法覆盖询价、竞价、报价、比价、一键下单、到货履约等采购协同过程。
2. “采购管理”又容易与库存管理中的采购申请、入库、出库混淆。
3. “供应链采购管理”同时覆盖供应商、商品、报价、竞价、采购订单、履约评价，能体现从供应商准入到采购履约的完整链路。

供应链采购管理的主责是供应商入驻、供应商后台、商品目录、询价竞价、报价、比价、采购下单、供应商履约和评价。它不替代库存管理、合同管理和财务管理：

1. 库存管理负责物料档案、采购申请、入库、出库、调拨、盘点和库存流水。
2. 供应链采购管理负责供应商商品、报价、竞价、平台比选和下单通知。
3. 合同管理负责采购合同、框架协议和合同归档。
4. 财务管理负责付款申请、应付、付款和账务处理。
5. 审批管理负责采购下单、供应商入驻、合同、付款等审批流程。
