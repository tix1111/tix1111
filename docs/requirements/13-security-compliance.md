# 涉密含党支部企业管理系统需求文档

> 本文件由根目录 `需求文档.md` 拆分而来，便于 GitHub 直接预览。完整总览请查看 `../../REQUIREMENTS.md`。

## 13. 涉密与安全合规要求

### 13.1 账号安全

1. 密码复杂度和定期修改策略。
2. 首次登录强制修改默认密码。
3. 登录失败锁定。
4. 会话超时自动退出。
5. 支持 IP 白名单或内网访问限制。

### 13.2 权限安全

1. 默认最小权限。
2. 系统管理员高危操作二次确认。
3. 角色权限变更记录审计日志。
4. 数据导出、附件下载、备份恢复必须记录日志。

### 13.3 数据安全

1. 数据库账号应使用最小权限账号，生产环境不建议使用 root。
2. 备份文件加密保存。
3. 涉密附件按密级分类管理。
4. 重要数据传输使用 HTTPS 或内网加密链路。
5. 页面展示敏感字段时按权限脱敏。

### 13.4 审计要求

必须记录：

1. 登录、退出、登录失败。
2. 用户、角色、权限变更。
3. 模块、菜单变更。
4. 业务单据新增、修改、删除、审批。
5. 附件上传、预览、下载。
6. 数据导出、备份、恢复。

### 13.5 涉密管理专项要求

1. 涉密对象必须经过定密、授权、使用、审计、解密或销毁的完整闭环。
2. 涉密项目、合同、附件、党建台账、工程资料应统一接入涉密对象表。
3. 涉密对象必须具备密级、保密期限、知悉范围、责任人、所属部门和审批记录。
4. 涉密下载、导出、复制、打印、外发必须有独立权限或审批流程。
5. 涉密载体必须记录编号、类型、密级、保管人、领用人、存放地点、状态和销毁记录。
6. 泄密事件必须记录事件等级、发现渠道、影响范围、处置过程、整改措施、追责结果和归档状态。
7. 涉密审计日志应防篡改，普通业务管理员不得删除或修改。
8. 涉密数据备份、恢复和迁移必须记录审批和操作日志。

### 13.6 党建管理专项要求

1. 党员信息必须与员工档案关联，避免形成两套人员主数据。
2. 党组织结构可与行政部门不同，不能简单等同于部门树。
3. 党员发展流程需要保留关键节点材料、审批意见和时间线。
4. 三会一课、主题党日、民主评议应形成计划、通知、签到、纪要、附件、归档闭环。
5. 党费标准、缴纳记录、欠缴提醒和统计应可追溯。
6. 党建学习依托培训管理课程和考试能力，但党建统计由党建管理汇总。
7. 党建资料涉及敏感或涉密内容时，必须同时应用涉密管理的密级和审计规则。
